# 车辆调度小工具 · 退役动力电池回收联单

- 行业：物流 / 动力电池回收
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`（含 `tsc` 类型检查）
- 规则自检：`npm run check:rules`

## 联单闭环

回收单扩展为 **登记联 / 运输联 / 接收联** 三联一体，流转状态：

`待派车 → 已派车 → 已完成`，数量或凭证异常时进入 `待复核`，复核完成后才 `已完成`。

1. **门店登记**：门店、电池包数量、最高温度、是否鼓包、备注。
2. **派车核查**：承运车辆、司机、原库位、运输时段；核查车辆与司机的时段占用：
   - 温度 **超过 45℃** 或 **电池鼓包** → 必须派 **带防火箱** 的车辆，否则报"车辆温度能力不符"并阻止派车；
   - 车辆/司机在其他在途联单的运输时段内 → 报"班次重叠"（车辆与司机分别说明原因）；
   - 车辆/司机/库位挂在待复核联单上 → 报"待复核未释放"，拦截派车；
   - 原库位被其他在途或待复核联单占用 → 报库位占用。
3. **到库录入**：实收包数、破损数、入库凭证号：
   - 实收 ≠ 出车包数 → "数量不符"停进**待复核**；
   - 有破损但缺凭证号 → "凭证缺失"停进**待复核**；
   - 待复核期间 **不释放车辆与原库位**，复核录入结论后才释放。
4. **冻结与改单**：派车确认后联单冻结；改单/改派必须填写原因，旧值、新值、原因全部保留在流转记录中；已完成联单不可再改。

## 分层结构（数据 / 规则 / 存储 / 页面分开）

| 目录 | 职责 |
| --- | --- |
| `src/types.ts` | 领域模型与接口定义 |
| `src/data/` | 门店/车辆/司机/库位档案与演示联单 |
| `src/rules/checks.ts` | 纯函数规则：防火箱、时段重叠、派车核查、到库核查 |
| `src/storage/local.ts` | localStorage 读写（业务数据与筛选条件分开存） |
| `src/store/recycle.ts` | Pinia 编排：调用规则、写流转历史、持久化 |
| `src/components/`、`src/App.vue` | 页面与弹窗，只与 store 交互 |

数据保存在浏览器 localStorage，重开页面后联单与"按门店、按车辆、按状态、联单号"的筛选条件都会保留。
