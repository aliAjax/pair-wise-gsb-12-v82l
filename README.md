# 动力电池回收联单调度台

退役动力电池从门店回库的"一联到底"调度小工具，由原来的只记出车，扩展为覆盖
登记 → 派车核查 → 到库接收 → 复核放行 → 改单留痕的回收联单。

- 行业：物流 / 退役动力电池回收
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 规则冒烟测试：`npm run test:rules`（36 项，覆盖班次重叠、温度能力、凭证、复核与改单留痕）

## 联单流程

1. **登记回收联单**：门店、电池包数量、最高温度、是否鼓包、承运车辆、司机、运输时段、原库位。
   登记后为「待派车」，可先记录再核查。
2. **派车前核查**（确认派车时强制）：
   - **班次重叠**：同一车辆或同一司机的运输时段与其他在途/待复核联单重叠 → 分别提示车辆/司机班次重叠；
   - **车辆温度能力不符**：最高温度超过 45℃ 或电池鼓包，却未派带防火箱的车辆 → 拦截，并给出防火箱改派建议；
   - 另含车辆容量不足、库位被占用、时段倒置等核查。
3. **联单确认后冻结**：状态进入「运输中」，车辆、司机、库位正式占用。
4. **司机到库录入**：实收包数、破损数、入库凭证号、接收人。
   - 实收数 ≠ 发出数（**数量不符**），或有破损却没填凭证号（**凭证缺失**）→ 自动进入「待复核」；
   - 待复核期间**车辆与原库位继续锁定，不释放**。
5. **复核处理**：补齐核实数量、凭证号并填写复核结论后放行，状态变为「已入库」，此刻才释放车辆与原库位。
6. **改单留痕**：冻结后改单必须填写原因；每次改单保留字段旧值 → 新值、原因、操作人、时间；
   待派车（未冻结）阶段可直接修改、不留痕。

## 分层结构（数据 / 规则 / 存储 / 页面分开）

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 数据 | `src/types.ts`、`src/data/seed.ts` | 领域模型、状态枚举、问题编码、初始演示数据 |
| 规则 | `src/rules/engine.ts` | 纯函数：防火箱判定、时段重叠、派车核查、到库核查、资源释放、联单号生成，不碰存储与 DOM |
| 存储 | `src/storage.ts` | localStorage 读写与版本迁移，不含业务判断 |
| 状态 | `src/stores/waybill.ts` | Pinia action 串联数据、规则与存储，改单留痕也在此落库 |
| 页面 | `src/App.vue`、`src/components/*` | 登记表单、联单列表（按门店/车辆/状态/关键字查询）、详情弹窗（核查/到库/复核/改单） |

数据保存在浏览器 localStorage（键 `dfwlfront-3-recycle-waybills`），重开页面仍可按门店、
车辆、状态查询，并保留车辆/库位占用与全部改单记录。页面上的「恢复演示数据」可一键重置。

## 状态与资源占用

| 状态 | 车辆/司机 | 原库位 | 可执行操作 |
| --- | --- | --- | --- |
| 待派车 | 未占用 | 未占用 | 派车核查、直接修改 |
| 运输中 | 已占用 | 已占用 | 到库录入、改单（留痕） |
| 待复核 | 锁定不释放 | 锁定不释放 | 复核处理、改单（留痕） |
| 已入库 | 已释放 | 已释放 | 只读查看 |
